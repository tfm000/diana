<objective>
Enable Fish (Fish Audio S2 Pro) on Apple Silicon as an EXPERIMENTAL engine by replacing the NVIDIA-only hardware gate with a tri-state GPU capability resolver. This corrects decision D-09's assumption that fish-speech is effectively NVIDIA-CUDA-only: fish-speech has native MPS support (PR #461, merged 2024-08-15), so Apple Silicon runs — but the fast paths (`--compile`/Triton, the SGLang streaming engine) are CUDA-only and S2-Pro-on-MPS is unverified upstream, so Apple Silicon is offered as EXPERIMENTAL (runs, but may be slow/unstable), never first-class.

Purpose: The target user is on an Apple M5 Pro (20-core GPU, 48 GB unified memory — far above the ~12 GB CUDA floor). Today the Fish row is shown-but-disabled on every Mac with a flat, now-false "requires an NVIDIA GPU with ~12+ GB VRAM" claim. After this change Fish becomes installable + usable on capable Apple Silicon behind the existing accept-once NC-license gate, while NVIDIA behaviour is unchanged and weak/unsupported machines still get an honest disabled reason.

Output: a tri-state `fish_capability()` in `gpu_probe.py` (tier in {cuda, apple, none}), `cuda -> mps -> cpu` device selection in the Fish worker, a broadened hardware gate in `fish_engine.py`, a tri-state Fish Settings row (+ matching Upload readiness note), updated tri-state tests, and an updated 05-HUMAN-UAT Fish section noting the M-series MPS install is now testable here.
</objective>

fish_capability() -> tuple[str, str, str] returning (tier, label, reason), tier in {"cuda","apple","none"}:

- "cuda": NVIDIA GPU >= FISH_MIN_VRAM_GB (12), decided by calling the existing capable_nvidia_gpu().
  Full support. reason is empty (or positive). label e.g. "NVIDIA GPU".
- "apple": sys.platform == "darwin" AND platform.machine() == "arm64" AND unified memory >= APPLE_MIN_UNIFIED_GB (16).
  Unified memory read torch-free via `sysctl -n hw.memsize` (bytes), // 1024**3 for GB. EXPERIMENTAL: reason/label
  state it runs on Apple Silicon via Metal/MPS but is experimental, slower than NVIDIA, unsupported upstream.
- "none": neither. reason explains it needs an NVIDIA GPU (~12+ GB VRAM) OR Apple Silicon (16+ GB unified).
  NEVER a flat "requires NVIDIA" claim.

Resolution order: check cuda first (capable_nvidia_gpu ok) -> else apple -> else none.
New constant: APPLE_MIN_UNIFIED_GB = 16.
Stdlib-only (shutil/subprocess/sys/platform), torch-free (assert no torch in sys.modules on the cheap path).
%-style logging only if logging is added.

Settings row mapping (the existing _render_heavy_engine_row consumes a (ok, vram, reason)-shaped gpu_gate and only
renders enabled/disabled — so the Fish call site must adapt the tier):
- tier "cuda"  -> gpu_gate ok=True (enabled exactly as today), no experimental caption.
- tier "apple" -> gpu_gate ok=True so the row FALLS THROUGH to the license/footprint/Install flow (ENABLED behind the
  accept-once NC-license gate + footprint confirm + disk pre-check), AND an "Experimental on Apple Silicon — runs via
  Metal/MPS, slower than NVIDIA, unsupported upstream" caption is shown on the row.
- tier "none"  -> gpu_gate ok=False with the honest reason (shown-but-disabled, key f"{engine}_install_disabled").
Drop the false flat "requires an NVIDIA GPU with ~12+ GB VRAM (none detected)" wording on Macs and the
