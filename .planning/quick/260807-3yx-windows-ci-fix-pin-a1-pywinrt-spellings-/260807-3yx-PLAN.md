# Quick Task 260807-3yx: Windows CI fix — pin the A1 PyWinRT spellings, UTF-8 reads, platform-aware argv

## Problem

The CI run after quick-260807-1o4 flipped `fail-fast: false`, so the four **windows** jobs executed
for the **first time ever**. All macOS and all ubuntu jobs are GREEN. Every windows job reports
**39 failed / 483 passed / 4 skipped**. Three distinct, evidence-pinned classes.

### Class A (~32 tests) — the WRONG PyWinRT static-member spellings. Assumption A1, now PINNED.

`diana/tts/native_os_engine.py` calls `SpeechSynthesizer.get_all_voices()` (lines **302**, **327**)
and `SpeechSynthesizer.get_default_voice()` (line **345**). Those methods **do not exist**.

The real API was verified against the official `winrt-Windows.Media.SpeechSynthesis` **3.2.1**
wheel stubs (unzipped for reference at
`/private/tmp/claude-501/-Users-tyler-Repos-diana/534aaec1-4b9e-4dd4-b13c-35b7efafad5a/scratchpad/winrt-stubs/`).
`SpeechSynthesizer` carries `metaclass=SpeechSynthesizer_Static`, and that metaclass exposes both
members as **properties**, not methods:

```
# speech/winrt/_winrt_windows_media_speechsynthesis.pyi:68-79
class SpeechSynthesizer_Static(winrt._winrt.IInspectable_Static):
    # ...get_AllVoices()
    @_property
    def all_voices(cls) -> typing.Sequence[VoiceInformation]: ...
    # ...get_DefaultVoice()
    @_property
    def default_voice(cls) -> VoiceInformation: ...
```

So the correct access is **class-attribute reads**: `SpeechSynthesizer.all_voices` and
`SpeechSynthesizer.default_voice` — no `get_` prefix, no parentheses.

**Everything else in the win32 branch is stub-CONFIRMED correct — do not touch it.** Already verified
by the planner, so the executor does NOT need to re-open the stubs:

| Symbol used by the engine | Stub evidence | Verdict |
|---------------------------|---------------|---------|
| `synth.synthesize_text_to_stream_async(text)` | speech `.pyi:88` | correct |
| `synth.voice` getter/setter | speech `.pyi:91` / `:94` | correct |
| `synth.options` | speech `.pyi:97` | correct |
| `options.speaking_rate` setter | speech `.pyi:115` / `:118` | correct |
| `VoiceInformation.display_name` / `.gender` / `.id` / `.language` | speech `.pyi:151-160` | correct |
| `SpeechSynthesisStream.size` | speech `.pyi:51-53` (property) | correct |
| `VoiceGender.MALE = 0`, `FEMALE = 1` | `speech/winrt/windows/media/speechsynthesis/__init__.py:31-33` (IntEnum) | correct |
| `Buffer(capacity)` ctor + buffer protocol | streams `.pyi:30-33` (`__new__(cls, capacity)`, `__buffer__`) | correct |
| `stream.read_async(buffer, count, InputStreamOptions)` | streams `.pyi:241` | correct |

**Why ~32 tests die from two bad names.** `diana/dashboard/pages/5_Settings.py:1555` calls
`_engine_default_voice(engine, ...)` at **page module level** → `NativeOSEngine.default_voice()` →
`_winrt_default_voice_id()` → `AttributeError` on win32. That kills the **entire Settings page**, so
every Settings AppTest and every Upload AppTest fails at import/run. The AppTests stub
`cached_voices`, so only the `default_voice` spelling is exercised live — but `all_voices` is equally
wrong per the stubs, just currently unexercised.

**Why the existing mocked tests did not catch it.** `tests/test_native_os_engine.py:189-190` builds
`speech_mod.SpeechSynthesizer = MagicMock(...)`. A `MagicMock` auto-creates **any** attribute, so
`get_all_voices()` "works" and returns an iterable `MagicMock`. The mock validated nothing. Worse,
`test_winrt_synth_reads_buffer` passes `voice=""`, which short-circuits the `all_voices` loop
entirely (line 301: `if voice:`). Both accessor spellings were untested.

### Class B (4 tests) — cp1252 vs UTF-8

`tests/test_native_voices_macos.py` reads the `say -v '?'` fixture with a bare `read_text()`.
On Windows the default locale is **cp1252**, and `tests/fixtures/say_voices.txt` contains byte
`0x9d` (undefined in cp1252) from non-ASCII voice names like *Amélie* → `UnicodeDecodeError`.

This is a latent **product** bug class too: a custom-voice transcript containing an em-dash would
crash a real Windows user. A bounded sweep is included.

### Class C (3 tests) — test-side path-separator assumptions

The **product is already correct** — it branches on platform in four places
(`orpheus_engine.py:141`, `f5_engine.py:172`, `fish_engine.py:215`, `install_state.py:149`,
`heavy_install.py:137`), and `paths.uv_binary()` returns `uv.exe` on win32.

The tests already *try* to be platform-aware:

```python
assert str(captured["cmd"][0]).endswith(("bin/python", "Scripts/python.exe"))
```

…but on Windows `str(Path)` renders **backslashes** (`...\Scripts\python.exe`), so the
forward-slash suffix never matches. The separator, not the branch, is the bug.

## Solution

Three tasks, in order. No engine redesign, no new features, no packaging changes.

1. **Pin the spellings** in the engine + make the mocked tests *actually pin* them (RED-check).
2. **Degrade, don't crash**: guard the `_engine_default_voice` probe on both pages + a new AppTest
   that reproduces the Windows cascade on macOS.
3. **Mechanical sweeps** (UTF-8 + platform-aware argv) + the full verification gate + commit.

### Scope guards (read before starting)

- **Do NOT change any other win32 spelling.** The table above proves the rest is correct. A
  "while I'm here" edit to `read_async`/`Buffer`/`display_name` would be an unverified regression.
- **`subprocess(..., text=True)` decoding is OUT OF SCOPE.** There are 12 such sites in `diana/`.
  They decode with the locale encoding and are the same *conceptual* class, but none are in the 39
  failures and changing them alters runtime decode behavior on live subprocess output. Note them in
  the SUMMARY as a follow-up candidate; do not touch them here.
- **The page guard does NOT mask the correctness bug.** The win32 spelling gate lives in the mocked
  engine tests (Task 1). The guard exists so that *one* engine's probe failure cannot take down a
  whole page — the same degrade-don't-crash discipline as T-04/05-LBLJSON.
- **`.planning/` docs keep the old spellings.** They are historical record (03-RESEARCH, 03-05-PLAN,
  03-05-SUMMARY, 03-05-WINDOWS-UAT-DEFERRED, 03-VALIDATION). The grep-proof gate is scoped to
  `diana/` and `tests/` only. Do not rewrite phase history.
- **Honest limitation.** There is no Windows box available. Windows confirmation is the *next CI
  push*. The SUMMARY must say so — never claim "Windows-verified".
