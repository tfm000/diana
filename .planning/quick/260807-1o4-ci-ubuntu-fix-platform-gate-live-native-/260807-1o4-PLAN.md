# Quick Task 260807-1o4: CI ubuntu fix — platform-gate the live native_os enumeration + stop fail-fast masking the matrix

## Problem

CI run **31133551107** (the re-run after quick-260807-0vj fixed the previous 8 failures):
`ubuntu-latest` / Python 3.11 reports **1 failed / 521 passed / 3 skipped**. The single failure is

```
tests/test_tts_registry.py::TestNativeOsVoices::test_native_os_dynamic_voices
RuntimeError: native_os TTS unsupported on platform: linux
```

raised by `NativeOSEngine.initialize()` (`diana/tts/native_os_engine.py:194-197`) via
`registry.get_engine_voices("native_os")` (`diana/tts/registry.py:120` — the D-04 dynamic branch
constructs + initializes a short-lived engine).

**The product is correct. The test is at fault.** Diana targets Windows + macOS (see the
platform constraint in `CLAUDE.md`); `NativeOSEngine.initialize()` deliberately raises a legible
`RuntimeError` on any other platform. Do **not** touch the engine or the registry.

The test (`tests/test_tts_registry.py:56-68`) was written on macOS — its own comment says
*"On macOS this exercises the real `say` path via the engine"* — and has **no platform gate**.
It bundles two separable assertions:

| Assertion | Platform dependence |
|-----------|---------------------|
| `assert not hasattr(NativeOSEngine, "VOICES")` — the D-04 static-vs-dynamic structural break | **independent** — must keep running on Linux and Windows too |
| `get_engine_voices("native_os")` + `hasattr(voices[0], "tier")` — live enumeration | **darwin-only** — shells the real `say` binary |

**Second, independent issue.** `jobs.test.strategy` (`.github/workflows/test.yml:12-15`) sets no
`fail-fast`, so it defaults to `true` and one job's failure cancels the whole 12-job matrix. This
has now masked results twice in a row:

- run 31129161528 — macOS failed first, cancelling ubuntu + windows entirely
- run 31133551107 — ubuntu-3.11 failed, cancelling **all four windows jobs** and 3 of 4 macOS jobs
  (only macos-3.11 completed, green)

A cross-platform product needs the full matrix report on every run.

> **Scope guard.** Turning off fail-fast will let the four Windows jobs actually run for the first
> time. If they surface Windows-specific failures, those are **out of scope for this task** —
> record them in the SUMMARY and raise a follow-up quick task. Do not chase them here.

## Solution

Two small, independent edits. No production code, no engine changes, no other test changes, no
matrix changes beyond adding `fail-fast`.

1. **`tests/test_tts_registry.py`** — split `TestNativeOsVoices.test_native_os_dynamic_voices`
   into an ungated structural test and a darwin-gated live test.
2. **`.github/workflows/test.yml`** — add `fail-fast: false` under `strategy:`.

### Why darwin-only and not `darwin` + `win32`

Deliberate. The win32 live path on a headless GitHub runner is unverified territory (no audio
subsystem guarantees, PyWinRT spelling assumption A1 still unpinned). Windows stays covered by:

- the **mocked** WinRT tests in `tests/test_native_os_engine.py` (`test_winrt_synth_reads_buffer`
  and friends — they run on every platform), and
- the deferred human Windows UAT:
  `.planning/phases/03-native-os-tts-new-default/03-05-WINDOWS-UAT-DEFERRED.md`.

CI must stay deterministic. **Record this rationale in the test comment** so a future reader does
not "helpfully" widen the gate to `("darwin", "win32")`.

(no `Args:`/`Returns:` docstring blocks), lazy in-body imports of `diana.*` symbols (the existing
`TestNativeOsVoices` body already imports inside the test — keep that).

## Threat model

| Boundary | Description |
|----------|-------------|
| GitHub-hosted CI runner → repository test suite | The workflow decides which jobs run and whether their results are reported |
| Test suite → OS `say` binary | The live native_os test shells a real subprocess on the runner |

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-1o4-01 | Tampering | `.github/workflows/test.yml` `strategy` | mitigate | Only the `fail-fast` key is added. No new actions, no version bumps, no `pull_request_target`, no secrets exposure, no added `pip install` — nothing new enters the supply chain, so no package legitimacy audit is required |
| T-1o4-02 | Repudiation | Matrix result reporting | mitigate | `fail-fast: false` is the fix itself — it removes the silent-cancellation blind spot that has twice hidden 11 of 12 job outcomes, so failures can no longer be masked by whichever platform fails first |
| T-1o4-03 | Denial of Service | 12 always-running matrix jobs | accept | Worst case all 12 run to completion instead of cancelling early; the suite is ~1 minute of CPU per job on a public-repo runner. Cost is trivially bounded and the visibility is the point |
| T-1o4-04 | Tampering | `pytest.mark.skipif` used to hide a real failure | mitigate | The gate is deliberately narrow: ONLY the live-`say` half moves behind it, the platform-independent D-04 structural assert stays ungated on every platform, and Task 2's linux simulation asserts both facts mechanically so a future widening of the gate breaks the check |
| T-1o4-05 | Elevation of Privilege | `say` subprocess on the runner | accept | Unchanged behavior, and now strictly narrower — the darwin gate means the subprocess is never reached on Linux. Existing list-argv / no-`shell=True` mitigations (T-03-06, V5) are untouched |
