# Quick Task 260807-0vj: CI fix — pytest-asyncio, custom_voices DB resolution, flash-pattern toasts

## Problem

CI run 31129161528 (repo `tfm000/diana`, the first CI run since April — the whole v1.0
milestone never ran on CI before): **8 failed / 514 passed** on `macos-latest` / Python 3.12;
the other 11 matrix jobs were fail-fast-cancelled. All three root causes were diagnosed and
**reproduced locally** in a CI-mirror venv (streamlit 1.61.1 + no pytest-asyncio + a fake
fresh `$HOME`). Do **not** re-diagnose — implement the fixes below.

**Root cause 1 — 6 async test failures ("async def functions are not natively supported").**
The workflow install step runs `pip install -r requirements.txt` then `pip install pytest`.
`pytest-asyncio` lives ONLY in pyproject's `dev` extra (`pyproject.toml:42`), so CI never
gets the plugin and `asyncio_mode = "auto"` (`[tool.pytest.ini_options]`, `pyproject.toml:64`)
is silently inert. Affected: `test_f5_engine.py::test_synthesize_carries_ref_and_gen_text`,
`test_fish_engine.py::test_synthesize_subprocess_shape`, `test_native_os_engine.py`
(`test_macos_synthesize_returns_wav`, `test_macos_real_synth_smoke`, `test_winrt_synth_reads_buffer`),
`test_orpheus_engine.py::test_synthesize_subprocess_cmd_and_stdin_json`.

> **Filename correction:** the diagnosis referred to `.github/workflows/tests.yml`. The real
> file is **`.github/workflows/test.yml`** (singular) — it is the only workflow in the repo.
> Edit that one; do not create a new file.

**Root cause 2 — `sqlite3.OperationalError: unable to open database file`**
(`test_custom_voices_apptest.py::test_saved_custom_voice_in_picker_and_browser_then_removable`).
`custom_voices._default_db_path()` (`custom_voices.py:79-83`) returns `str(paths.db_path())` —
the raw platformdirs path — bypassing the config entirely. Call chain:
`registry._f5_voices()` / `_fish_voices()` (`registry.py:155`, `:185`) → `list_custom_voices()`
with no `db_path` → `_default_db_path()` → `_name_for(db, vid)` → `get_setting` →
`sqlite3.connect` on a path whose parent dir does not exist on a fresh machine (a CI runner has
no `~/Library/Application Support/Diana`). It also means wrong-DB reads whenever
`storage.database_path` is customized. Every other caller (`voice_labels`, `install_state`) is
handed `config.storage.database_path` explicitly — this one function is the outlier.

**Root cause 3 — invisible success toasts**
(`test_uninstall_apptest.py::test_uninstall_confirm_flow_deletes_and_clears_cache`,
`AssertionError: a success message reports the freed space`).
`5_Settings.py` has three `st.success(...)` calls IMMEDIATELY followed by `st.rerun()`:
Piper voice uninstall (`:627`), custom-voice remove (`:674`), heavy-engine uninstall (`:850`).
The rerun discards the just-rendered success element, so **real users never see the freed-space
confirmation** — a genuine UX bug. It was masked because streamlit 1.56's `AppTest` does NOT
follow an `st.rerun()` inside `.run()` (the captured tree is the pre-rerun one), while CI's
streamlit 1.61.1 DOES (post-rerun tree, message gone).

## Fix

1. Workflow: `pip install pytest` → `pip install pytest pytest-asyncio`.
2. `_default_db_path()` resolves through `get_config().storage.database_path` (whose default
   value already IS `str(paths.db_path())`, so in-app behavior is unchanged), plus `_name_for`
   degrades to the id-derived fallback instead of raising when the DB cannot be opened.
3. Flash-message pattern: stash the message in `st.session_state` before `st.rerun()`, then
   render-and-pop it once at the top of the Voices tab — so the confirmation appears AFTER the
   rerun regardless of which of the three actions produced it. Make the affected assertion
   tolerant of both AppTest rerun semantics so the same test file is green on 1.56 and 1.61.

## Threat model

| Boundary | Description |
|----------|-------------|
| CI runner → PyPI | The workflow install step pulls packages on a hosted runner |
| App → per-user SQLite DB | `custom_voices` enumeration opens a DB path resolved from config |
| User → Streamlit session state | Flash message text is written to and read from `st.session_state` |

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-0vj-01 | Tampering | `.github/workflows/test.yml` install step | mitigate | Only `pytest-asyncio` is added, and it is already a declared project dev dependency (`pyproject.toml:42`) already installed in the local `.venv` — no new third party enters the supply chain, so no legitimacy audit is required |
| T-0vj-02 | Denial of Service | `custom_voices._name_for` → `sqlite3.connect` | mitigate | An unopenable/erroring DB is caught (`sqlite3.Error`) and degrades to the id fallback, so a broken DB cannot crash voice enumeration (and with it every picker + the cross-engine browser) |
| T-0vj-03 | Information disclosure | `_default_db_path` reading a config-supplied path | accept | The path is developer/user-owned local config already trusted by every other DB caller; this change makes the module CONSISTENT with them rather than adding a new trust source |
| T-0vj-04 | Tampering | `st.session_state[_VOICES_FLASH_KEY]` | accept | Values are app-generated freed-space strings rendered via `st.success` (no `unsafe_allow_html`); session state is per-session and not user-supplied |
