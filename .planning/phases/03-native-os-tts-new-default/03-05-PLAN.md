<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| document text → WinRT SpeechSynthesizer | Untrusted document chunk text crosses into the OS speech API |
| pip → build environment | Installing Windows-only C-extension wheels |
| WinRT stream → bytes | Synthesized audio bytes pulled from a COM stream buffer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-14 | Tampering | document text → `synthesize_text_to_stream_async(text)` | mitigate | Text is passed as a single API argument to the WinRT method (a managed API call, not a shell) — no shell, no interpolation; the WinRT API treats it as data (V5). |
| T-03-15 | Tampering | npm/pip/cargo installs (the four winrt-* packages) | mitigate | All four legitimacy-audited in RESEARCH (slopcheck [OK], source `github.com/pywinrt/pywinrt`, PyPI 3.2.1) — Approved, none [ASSUMED]/[SUS]/[SLOP], so no per-package blocking checkpoint. Platform-gated to win32 so they never enter the macOS/Linux build set. (T-03-SC.) |
| T-03-16 | Spoofing / Info Disclosure | unexpected cloud call (e.g. edge-tts) | mitigate | WinRT `SpeechSynthesizer` is the LOCAL OS engine; `edge-tts`/cloud is explicitly forbidden and not imported. No socket/network import in the engine — verified by `<verification>`. |
| T-03-17 | Denial of Service | huge text / hung WinRT synth | accept | Per-call text is bounded by `processing.chunk_max_chars`; WinRT synth is in-process and fast. No subprocess timeout applies (not a subprocess); the chunk bound is the control. |
| T-03-18 | Tampering | untrusted/stale voice id → `synth.voice` | mitigate | Voice match loops the live `get_all_voices()` and only sets `synth.voice` on an exact id match; an unmatched id leaves the system default in place (no crash). UI-layer validation (Plan 04) further guards stored ids. |
</threat_model>
