## Phase Goal

**As a** power user, **I want to** install Orpheus on demand and narrate with its named voices entirely in-app, **so that** I get a higher-quality CPU-viable neural voice without a terminal and without bloating the default install.

This is the first vertical slice: install -> select -> synthesize, end-to-end, for Orpheus — the lowest-risk engine (torch-free via `orpheus-cpp` + prebuilt `llama-cpp-python` wheels) that proves the whole heavy-engine scaffold (05-02 cheap path + 05-03 uv provisioner). It also establishes two generic surfaces the F5/Fish slices reuse: the Settings heavy-engine install row (built on the Kokoro-row machinery) and the Upload D-16 fail-fast Convert gate (built on `heavy_engine_failfast`, which already covers all three heavy engines).

Orpheus mirrors the Kokoro single-model precedent (engine-level model, 8 named voices baked in — Phase-4 D-19) and the subprocess-engine discipline of `native_os`/`piper`. The heavy SDK (`orpheus_cpp`, `llama_cpp`) lives ONLY in `heavy_workers/orpheus_worker.py`, run by the venv's Python — never imported in the app interpreter.

Purpose: deliver HEAVY-01 and prove the scaffold end-to-end before F5/Fish layer on.
Output: Orpheus installable + selectable + synthesizing; `test_orpheus_engine` + `test_registry_heavy` green; UI human-verified.
