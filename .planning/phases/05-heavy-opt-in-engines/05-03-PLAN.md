## Phase Goal

**As a** power user, **I want to** install a heavy neural engine's Python deps and model weights with one in-app action and zero terminal, **so that** I can use higher-quality voices without touching a command line.

This plan builds the load-bearing new capability of Phase 5: `diana/tts/heavy_install.py`, the bundled-`uv` provisioner. Phase 4 only downloaded files; this PROVISIONS an isolated Python environment. The mechanism (RESEARCH Pattern 1 + 3): drive a bundled `uv` standalone binary via `subprocess` to create a per-engine venv with a pinned standalone CPython 3.12 and `uv pip install` the heavy deps, then prefetch the weights via the venv's own Python with `HF_HOME` pointed at the per-user cache — streaming two-phase progress into the shared `dl_state` dict that the Settings `@st.fragment` poller renders. Nothing here imports torch/llama-cpp; the heavy SDKs live only in the venv.

It also lands the accept-once NC-license helpers (D-08, consumed by F5/Fish) and a first-of-its-kind stack verification task that re-confirms the fast-moving package versions / wheel availability / model repo IDs before they are pinned (RESEARCH Assumptions A1-A8).

Purpose: this is the D-05/D-06 RESEARCH FLAG resolved as real code, not a TODO. It is the substrate the three engine slices (Waves 4/5/7) each prove end-to-end.
Output: `heavy_install.py` green against `tests/test_heavy_install.py` + `tests/test_license_gate.py` (subprocess fully mocked); confirmed exact-version pins recorded for the engine slices.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → network (PyPI / abetlen index / HuggingFace) | Untrusted bytes: pip packages + model weights crossing into a venv on disk |
| app → bundled uv binary (subprocess) | An executable is invoked; its path and identity must be trusted |
| app → venv subprocess (weight prefetch) | The venv Python runs with HF_HOME pointing into the per-user cache |
| background install thread → Streamlit session | The thread must not cross into st.* (ScriptRunContext) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-SC | Tampering / Elevation | `uv pip install` of multi-GB packages + weight download (HIGH) | mitigate | Task 1 pins every package to an exact, re-verified version; install ONLY from PyPI + the abetlen wheel index + pinned/ungated HF repos; legitimacy audit (RESEARCH) clears all packages; the in-app D-04 footprint confirm + D-08 license accept are the human gates before any byte |
| T-05-EXE | Tampering / Elevation | bundled uv binary path trust | mitigate | Task 2 resolves uv via `paths.uv_binary()` (bundled, Phase 6 ships the signed release) — never a PATH lookup except an explicit dev fallback; list argv, `shell=False` |
| T-05-CMD | Tampering / Elevation | subprocess argv (package names / paths) | mitigate | Task 2 uses list argv exclusively, no shell string; package/version values are code-pinned, not user input |
| T-05-GGUF | Tampering | untrusted GGUF/weights | mitigate | Task 1 pins HF repo + revision; HF download is hash-verified; ungated repos only (no token handling); `download_file` md5+atomic for any single-URL asset |
| T-05-DISK | DoS | multi-GB install fills disk | mitigate | Task 2 `has_space(venvs_dir(), deps+weights)` before any byte (D-04/D-05); installs serialized by the UI spawn-guard (reused in engine slices) |
| T-05-SRC | DoS (app crash) | install thread touching st.* | mitigate | Task 2 `install_engine` writes ONLY the shared `state` dict; the `@st.fragment` poller (existing) renders — the proven Phase-4 discipline |
</threat_model>
